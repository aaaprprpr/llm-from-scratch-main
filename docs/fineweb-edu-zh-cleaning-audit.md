# 当前 Fineweb-Edu-Chinese-V2.1 数据清洗审查

日期：2026-09-22。检查的是训练机 `192.168.1.3` 上的 `/media/tdt/新加卷/llm-from-scratch-main`，不是根据本机配置猜测。此次只读检查、抽样和模拟筛选，没有替换正在使用的语料、bin 文件或训练配置。

## 结论

**需要针对性清洗，现有数据集仍可作为预训练主体。** 第一优先级是中文语言筛选，其次是篇内重复和网页附加内容。需要按 token 预算观察来源/领域比例，不能只看文档条数。当前最明确的预算偏差是长篇英文专业文献。

这不等于“整个库都是坏文本”：英文论文可以是有效专业语料，但不适合大量占用一个 62M、中文日常表达优先模型的预算。也不能期待清洗本身修复上次发现的优化失稳或自动产生多轮聊天能力。

## 当前到底用了什么

远端下载配置、预处理配置、实际元数据一致：只启用了 `fineweb_edu_zh_4_5`，即 `opencsg/Fineweb-Edu-Chinese-V2.1` 的 `4_5/*.parquet`。原始记录数为 17,790,513。

一个 Hugging Face 数据集内部包含多个 `source`。本次完整文档样本中实际看到 10 个来源：IndustryCorpus2、Map-CC、CCI3、ChineseWebText、TeleChat、SkyPile、WuDao、Wanjuan、OpenCSG-CC、MiChao。

[官方数据卡](https://huggingface.co/datasets/opencsg/Fineweb-Edu-Chinese-V2.1) 将 4–5 档描述为教育内容质量分档。[技术报告](https://arxiv.org/html/2501.08197v1#S3.SS1) 说明了多来源汇集、教育价值评分和 MinHash 去重流程。教育价值评分没有直接保证文档以中文为主，也没有直接衡量其是否适合日常对话。

本地实际 `score` 字段在 4096 篇样本中的范围为 **0.800293～0.915039**。不能仅根据目录名就新增 `score >= 4` 的过滤条件，否则会误删这里的样本。抽样范围也不能当作全库 score 的最大最小值。

## 本次抽样方法

- 在全部 17,790,513 篇原始文档中，seed=2026092201，无放回随机抽取 4096 篇完整文档；抽取后按索引排序仅为减少 I/O。
- 使用现有 `clean_record` 做基础规范化，使用训练用的 24,576 词表 tokenizer 计算完整文档 token 数（含一个 EOS）。
- 共计 7,351,153 tokens，所有 4096 篇均通过现有清洗。
- 中文比例定义为 `汉字数 / 所有 Unicode 字母字符数`，覆盖基本及扩展汉字区，忽略数字、标点和空白。它是可解释的语言筛选启发式，不等于经过校准的语言识别模型。
- 保留逐文档的 index/source/score/语言比例/token 数/重复指标，以及供人工复核的首尾文本和重复句例。
- 本次不是全量语料扫描，也没有运行全库近重复或训练/验证泄漏检测。

| 项目 | 完整文档样本结果 | 解释 |
| --- | ---: | --- |
| 中文比例 <20% | 619 / 4096 篇，约 15.1% 文档、26.28% tokens | 长文档放大 token 占比；样本中全部来自 IndustryCorpus2 |
| 中文比例 <60% | 633 篇，26.80% tokens | 多数明显非中文文档已被低阈值覆盖 |
| 中文比例 <70% | 667 篇，27.57% tokens | 包含部分混合语言技术文章，不应一概称为垃圾 |
| 中文比例 <80% | 772 篇，29.71% tokens | 更严格阈值开始排除更多正常中英混合技术正文 |
| 篇内长句重复比例 >30% | 9 篇，涉及 0.66% 样本 tokens | 发现正文重复拼接、相同段落反复出现 |
| 页脚/导航行标记命中 | 64 篇 | 多数应局部删行，不应整篇删除；不能据此声称 64 篇全是坏数据 |

| 样本内规范化全文完全重复 | 0 组 | 小样本不足以证明全库没有重复，亦不支持断言全库严重重复 |

文档长度中位数为 1032 tokens，P90=3112、P95≈4701、P99≈15496。长文应按语言/内容质量处理；不应因为训练窗口为 2048，就把所有更长的好文章丢掉。

对“中文比例 <70% 所占 tokens”的文档重采样 bootstrap，近似 95% 区间约为 23.8%～31.1%。27.57% 是样本估计，不是全库精确统计。上次从实际 train.bin 随机抽取 token 窗口得到约 28% 低中文占比窗口，方向上与本次完整文档检查一致，但二者抽样单位和阈值不同。

## 人工复核的具体问题

- 英文医学论文：原始记录有大段英语正文、文献引用、表格和 LaTeX；最长样例超过 6 万 tokens。原文已经如此，不是 bin 解析出错。
- 篇内重复：原始索引 `6067264` 的移动学习文章出现重复正文；`8463197` 的症状说明重复拼接；`11032065` 的研究摘要多句重复 4 次。这些文本均通过现有“极端重复”检查。
- 网页附加内容：`588922` 包含首页导航、栏目分隔及责任编辑；有正文完整的文章附带免责声明。适合删除确定的导航/页脚，保留正文。
- 阈值误伤风险：`679066` 的 SOA 技术文章中文比例约 59%，`936925` 的 cgroups 说明约 68%。它们是正常中英混合技术文档，若从本次中文主池排除，应称为目标筛选，不应称为乱码或坏数据。

## 现有清洗的缺口

当前 `data_pipeline/preprocess.py` 做 ftfy/NFC、控制字符清理、空值/纯链接/无字母/替代字符比例检查。重复检查主要针对前 4096 个字母数字字符中的单字符极端集中或完全周期模式，难以发现重复正文和重复长句。

实际报告：17,790,513 条只过滤 748 条（约 **0.0042%**），其中 747 条为乱码、1 条为纯链接，重复过滤为 0。过滤率低本身不能证明代码错；本次 619 篇低中文样本和 9 篇重复样本全部通过，直接说明它没有覆盖这些目标。

`text_only` adapter 在 map 前只保留 `text`，导致 source、score 被丢弃；清洗报告也没有按 token、语言和内部来源统计。建议保留这些字段或等价的旁路索引用于审计，不要把元数据拼进训练正文。

## 建议规则及样本试算

建议先保留一个以中文为主的池，同时保留可追溯的排除原因：

1. **语言优先。** 中文比例 <20% 的文档从本次中文主池排除；20%～70% 的混合语种/代码/技术文档单独归档；主池以 ≥70% 为起点。正常人名、英文缩写仍可存在。上线前继续复核阈值附近的样例。
2. **篇内重复。** 优先去除明显重复的完整段落；对于仍有大段循环拼接的文本再过滤。不要把正常引用、诗歌副歌、公式或短标题重复一律判坏。
3. **网页结构。** 只删除可确认的导航、下载诱导、独立推广和页脚行。不能因为正文出现“法律”“医学”“版权”或“责任编辑”等单个词就删除整篇。
4. **去重与切分。** 先记录规范化 hash 并测量全库精确重复，再根据剩余情况决定是否增加近重复检测；按重复组划分 train/val。官方已经报告过上游 MinHash，现阶段不把全量重跑昂贵近重复当作最高优先级。
5. **按 tokens 控制来源和长度。** 优先保留自然叙述、生活常识、科普等正文；专业领域采用 token 配额，不能仅凭文档数配比。高质量长文可按自然章节处理，不粗暴截断到训练窗口长度。
6. **补充统计。** 保存 source、原始 index、语言比例、清洗前后 token 数、过滤原因及文档 hash。对中文日常文本建立固定验证子集，另报其 loss。

样本保守模拟：语言阈值 + 至少 100 个非空白字符/50 个汉字 + 重复长句比例 ≤30%。为估算预算，这里直接排除重度重复文档；实际若能去重段落再保留，保留量可能稍多。以下没有声称全部保留项均通过人工质量评审。

| 主池中文阈值 | 保留文档数 | 保留文档比例 | 保留 tokens 比例 |
| --- | ---: | ---: | ---: |
| ≥60% | 3455 / 4096 | 84.35% | 72.89% |
| **≥70%** | **3421 / 4096** | **83.52%** | **72.12%** |
| ≥80% | 3316 / 4096 | 80.96% | 69.98% |

因此可以先用 ≥70% 作为中文主池的试验阈值，保留混合语言池供后续复核，避免一次性不可追溯地删除。没有必要先扩大下载范围。

当前训练仍在读取旧 bin。实施清洗时应写入独立的 `preprocessed_zh_v2` 和 `train_zh_v2.bin` / `val_zh_v2.bin` 等新路径，生成新的统计和 tokenizer 指纹元数据后再启动新实验；不要在训练进行中替换同名文件。词表保持 24,576，无需重训 tokenizer。
