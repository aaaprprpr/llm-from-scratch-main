# 2026-09-22 远端预训练实测

## 结论

本次训练已经出现实质性退化，不能归因于“还没训练够”或仅仅“不擅长聊天”。同时存在数据目标不匹配和明显的优化失稳迹象。建议先停止按当前配置长跑，保留已有 checkpoint，优先建立稳定的优化器对照。此次检查没有中断远端进程，也没有修改远端代码、配置、数据和 checkpoint。

本报告没有通过长程优化器 A/B 实验唯一确定根因；`Muon lr≈0.02 + weight_decay=0` 是当前优先排查的配置组合。不能把“Muon 算法本身有问题”或“只加一个 weight decay 就一定恢复”当作已证明结论。

上次审查保留了这组 Muon 参数，并把它描述为保守起点，依据不足。单步合成数据测试只验证执行路径与有限值，不能验证几千步后的稳定性。本次真实训练证据推翻了对这组参数可以直接长跑的判断。

| ---: | ---: | ---: | ---: | ---: |

| 30,000 | 5.0478 | 4.9465 | 140.69 | 73,509.2 |

原始日志在 4,500 步达到目前最低 val loss=3.5336，但没有保存 4,500 步 checkpoint。已有 checkpoint 中，5,000 步明显好于 30,000 步。

5k 到 30k，32 个验证窗口 **全部恶化**，单窗口 loss 增幅为 0.570～1.774，中位增幅 1.297。固定 train 样本也恶化。因此不能用某一个抽样窗口、单次随机生成、只是不适合对话或一般的“训练 loss 降、验证 loss 升”过拟合现象解释全部证据。

训练日志中的 `loss` 是当步顺序读取的一批数据，不等于这里的固定 train loss。个别当步 loss 降到 2.x，不能说明全局语言能力恢复。

## 生成和推理检查

5k 和 30k 各用 9 个提示、temperature=0.3/0.7、top_p=0.9、固定种子、最多 80 新 tokens，总计 36 次生成。提示覆盖常识填空、人物位置、日常续写、故事、技术文章和招呼。

30k 示例，temperature=0.3：

```text
输入：中国的首都是
续写：中国最大的国,也是中国在世界,也是中国在发展中国家……

输入：近年来，随着计算机技术的发展，人工智能在
续写：,我国互联网技术的发展,我国数字经济,人工智能产业……新业态、新业态、新业态……
```

5k 也存在明显复读和常识失败，不能当成已经可聊天的模型；但其技术文章续写相对连贯，固定集合 loss 明显更好。30k 降低温度仍然出现偏题、重复和语义破碎。

四项简单常识/上下文探针在两种温度下，两份 checkpoint 均未命中预设正确开头。这里只是小规模诊断题，不是标准 benchmark。重复率也不能单独当作质量指标：30k 可以从“重复连贯模板”变成“少重复但语义破碎”，即使重复率下降也不代表能力提高。

FP32 下，所选人物位置提示的 16 步 KV-cache 与完整重算，在四份 checkpoint 上 top-1 均为 16/16 一致。5k / 30k 最大 logit 差约 1.24e-4 / 6.77e-5。这个局部测试未发现缓存错误，不构成对所有缓存路径的完整证明。

## 优化失稳证据

| 训练区间 | 裁剪前 grad_norm 中位数 | 95% 分位 |
| --- | ---: | ---: |
| 1k～3k | 0.246 | 0.404 |
| 3k～5k | 0.484 | 0.946 |
| 5k～10k | 9.195 | 45.351 |
| 10k～15k | 74.343 | 330.488 |
| 25k～约30.5k | 123.257 | 485.006 |

该值是 `clip_grad_norm_` 返回的裁剪前范数；不能误称“实际更新使用了未裁剪的 123 倍梯度”。

隐藏权重和激活尺度持续增长：QKV 矩阵 RMS 的层平均从 5k 的 0.258 增至 30k 的 0.690；相同中文输入的末层残差 RMS 增至约 78 倍。所有检查的权重仍为有限值；没有 NaN 不代表训练健康。

额外在一个固定验证窗口的前 256 tokens 上探测实际 RoPE 后的注意力，排除前 32 个 query：

- 5k：按层平均，约 81.8% 的 head/query 对将超过 99% 的注意力概率放在同一个 key 上。
- 30k：该比例约 99.0%，注意力接近完全饱和。

某些注意力头本来就可以很尖锐，单个饱和率不能独立证明故障；这里它与参数增长、激活增长、梯度增长和固定 loss 恶化共同构成失稳证据。

30k checkpoint 中 Muon LR=0.019286，仍为峰值 0.02 的约 96.4%，weight_decay=0；顶层的 0.1 只作用于 AdamW 的 embedding 组。长余弦计划并没有在退化期间明显降低 Muon 的更新幅度。

[Muon 原作者说明](https://kellerjordan.github.io/posts/muon/) 中的正交化会对矩阵更新做归一化，因此通常不能指望把原始梯度裁剪到 1 就按相同比例压小最终 Muon 步长。还需要控制学习率、权重尺度和稳定性。

作为有限的推理诊断，保持权重不变，仅把 Q/K 各缩小后复测：30k 最佳试验因子 1/16，在同一整套验证窗口上只从 4.9465 改善至 4.8663。它没有恢复到 5k 的水平，也没有作为修复部署；这些因子是探索性测试，不是经过独立验证的新配置。

## 数据问题：确实存在，但不足以独自解释训练退化

远端只启用了 `fineweb_edu_zh_4_5`，预处理报告也记录只有一个来源。并没有混入配置中列出的 Wiki、TigerResearch 或对话数据。

以 seed=20260922，在 train/val 各按 token 位置均匀随机抽取 1024 个 256-token 窗口。统计字符中的字母字符，中文汉字低于这些字符的 20% 时记为“低中文占比”：

| 抽样 | 低中文占比窗口 | 占比 | 中文占比 ≥80% 的窗口 |
| --- | ---: | ---: | ---: |
| train | 288 / 1024 | 28.13% | 697 / 1024 |
| val | 270 / 1024 | 26.37% | 713 / 1024 |

这估计的是随机 token 位置附近的语言分布，不是精确的全文 token 语言比例，更不是文档数量比例。抽看低中文窗口主要为英文医学、生物学论文，含 Markdown 引用和表格。长篇英文论文会占用小模型的 token 预算，而文档数可能看起来不多。

进一步直接读取下载目录下 12 个分散 Arrow 分片、各前 5 条记录：在 `source=IndustryCorpus2` 的原始样例中已经看到纯英文医学正文。因此这些样例不是 tokenizer 错配或 bin 字节解析造成的。这个原始记录检查用于确认来源，不用于估计各 source 的全局占比。

预处理从 17,790,513 条中只过滤了 748 条（约 0.0042%）。它主要处理空值、乱码等基础问题，没有达到“中文日常表达优先”的语言、领域、重复和模板质量筛选要求。中文抽样也包含大量专业论述、政务/新闻和推广文章，不能将“教育高分档”直接等同于“适合 62M 中文聊天模型”。

抽样 token ID 均在词表范围内，tokenizer 哈希匹配；可读中文和英文均可正常解码。这里只做了抽样，没有全量扫描约 600 亿字节的 train.bin，也没有完成全局去重/训练验证泄漏审计。

## 建议的下一步

1. **先暂停当前长跑，保留 5k 与 30k 文件。** 30k 不是比 5k 更好的基础；继续同配置跑到 228k 不应视作解决办法。此次操作未替用户停止进程。
2. **先建立优化器对照，再做昂贵的全量重训。** 在同结构、同词表、同训练样本顺序和同验证窗口下，用全 AdamW（起点 LR=3e-4、betas=(0.9,0.95)、矩阵 weight_decay=0.1、norm 不衰减、梯度裁剪=1）作稳定性基线。至少观察越过原来约 4.5k～5k 的退化起点，不能再次把单步成功当作可长跑证明。这是待验证方案，没有在本次审查中跑完。
3. 若继续探索 Muon，应单独对比更低 LR（例如 0.003～0.005）和非零 weight decay（例如 0.1），监测 Q/K、残差 RMS 和固定验证 loss。上述数值是试验起点，不是已经验证的最终配置。加入 QK normalization 也是候选，但属于架构变化，应独立验证，不能混在一次改动里宣称定位根因。
4. 稳定性确定后再重建更符合目标的数据：语言过滤、按 token 预算控制长英文/专业文献占比、清理网页模板和近重复，增加自然中文叙述与生活常识；保留来源/语言统计，单独设中文日常文本验证集。词表仍可保持 24,576。
5. 如从 5k 做恢复实验，需要注意当前 `load_state_dict` 会恢复旧优化器 param groups。只在 JSON 中改 `weight_decay` 后普通 resume，旧 checkpoint 中的 0.0 可能覆盖新值；需要显式覆盖恢复后的参数组或只加载模型权重重建优化器。本次没有修改恢复逻辑，也没有生成一个未经检验的“恢复配置”。
