虚拟环境为什么突然不能运行

本次故障的直接原因是 Python 入口的符号链接无法解析。运行 .venv/bin/python 时，Shell 返回“没有那个文件或目录”；但链接本身存在，它在当前挂载方式下显示的目标却是 unsupported reparse tag 0xa000000c。系统因此找不到要执行的解释器，pip 和清洗脚本也会一起失效。

项目所在 NTFS 分区当前使用 fuseblk 挂载。全量检查发现 .venv/bin/python 与 .venv/lib64 两个链接有相同问题。原始 Conda Python 3.12.13 仍可运行，已安装的包也仍在。这些证据支持“当前挂载方式无法解释这两个 NTFS 链接”；本次检查无法确定链接此前是否被 Windows 改写，或是否由挂载驱动切换触发。

修复时将原基座 /home/tdt/anaconda3/envs/torch/bin/python3.12 复制为 .venv/bin/python 普通可执行文件，让 Python 入口不再依赖这个损坏的链接；同时重新建立 lib64 → lib。原链接保存在 .venv/repair-backup-20261006/，虚拟环境配置和已安装依赖继续使用原文件。

NTFS 上的 Linux 符号链接跨挂载方式使用时需要留意兼容性。当前解释器入口已经改成普通文件；如之后再次出现同类错误，先查看链接目标和挂载方式，再决定是否需要处理环境依赖。
