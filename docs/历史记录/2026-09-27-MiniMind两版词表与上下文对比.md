# MiniMind 两版最终预训练权重对比（2026-09-27）

> 历史评测（2026-10-05 整理）：同时改变了词表、参数量和训练长度，不能据此单独判定 8K 词表或 32K 窗口的优劣。当前默认已回到 24K/2K，见 [预训练说明](../../train/pretrain/README.md)。本机目前缺少本次逐条结果 JSON 和两版最终 checkpoint，以下数值保留为当时记录，不能声称已在本轮重新复测。

## 结论

对当前两版最终 checkpoint，**24K 词表 / 4K 上下文版本在短文本续写与这组同文验证样本上更强**。8K 词表 / 32K 上下文版本的训练日志 token loss 更低，但更换词表后这个值不能直接跨版本比较；按同一批原文的 UTF-8 字节数归一化，8K 版损失反而高约 7.2%。8K 版可以处理约 30K token 的输入，也能利用紧邻问题的事实，但本次开头事实检索探针在 3K～30K 均失败，尚不能据此认为它具有可靠长程记忆。两个模型都是预训练权重，尚未达到稳定问答或对话的水平。

## 对象与方法

| | 24K / 4K | 8K / 32K |
| --- | ---: | ---: |
| run / 最终步数 | `run_20260923_130232` / 13,248 | `run_20260924_005318` / 14,137 |
| 参数量 | 61,945,920 | 52,508,736 |
| 词表 / 模型上下文 / 训练序列 | 24,576 / 4,096 / 2,048 | 8,192 / 32,768 / 32,768 |
| 训练 token | 1,736,441,856 | 1,852,964,864 |
| 日志最终 val loss（各自 token） | 2.1498 | 2.0929 |

两份 bin 的元数据记录同一原始 `pretrain_t2t.jsonl` 指纹、同一随机切分种子和 423,441 条验证记录。评测程序在两个 bin 的对应位置解码，逐条核对文本相同。从整个验证记录序列等距取 240 个候选位置，保留 150～3,000 UTF-8 字节且两版均不超过 2,048 token 的记录，再在合格记录中等距选 64 条，覆盖记录序号 100～423,340。总文本 44,411 字节。每条以 EOS 作为前缀，预测全文 token 及末尾 EOS；累计负对数似然除以原文字节数和 ln(2)，得到 bits per byte（BPB，越低越好）。本次是固定、小规模诊断样本，不是完整验证集评测。用 BF16 前向、FP32 交叉熵，在 RTX 5070 Ti 上运行。

生成比较使用相同的 11 个提示，temperature=0.3、top_p=0.9、最多 80 个新 token，固定随机种子；另对其中 7 个提示各取 3 个种子，temperature=0.7。不同词表下相同随机种子并不产生等价 token 抽样。明确答案的“命中”只检查续写开头是否为指定文本，不能代替整段正确性。

## 同文验证结果

| 指标 | 24K / 4K | 8K / 32K |
| --- | ---: | ---: |
| 64 条同文记录上的 BPB | **0.8595** | 0.9217 |
| 这 64 条编码 token 数（含 EOS） | 11,129 | 11,876 |
| 逐记录 NLL 更低 | **63/64** | 1/64 |
| 固定低温：明确答案开头命中 | **5/6** | 2/6 |
| 常规温度：明确答案开头命中 | **5/15** | 0/15 |

8K 减 24K 的 BPB 差为 **+0.0622**，相对 24K 约 **+7.2%**。对这 64 条记录做配对重采样，差值的 95% bootstrap 区间为 **[+0.0516, +0.0743] BPB**；该区间只描述这套抽样的波动，不能覆盖训练/验证重复、数据分布选择等系统误差。8K 对相同文本多用约 6.7% token，所以单 token loss 的降低并不代表按原文的信息量更好。

## 实际续写

| 提示 | 24K / 4K 低温续写开头 | 8K / 32K 低温续写开头 |
| --- | --- | --- |
| `中国的首都是` | `北京的。` | `中国著名的诗人之一……` |
| `2加3等于多少？答案：` | `5` | `答案是4。` |
| 红色钥匙在左抽屉 | `左边抽屉，蓝色钥匙在右边抽屉。` | `左边，蓝色钥匙在右边。` |
| 张华在上海、李明在北京 | `上海，李明住在上海……` | `北京。` |
| `你好，我是` | `你的AI助手。我可以帮助你完成各种任务……` | `我的同事，我很喜欢和同事在一起。` |
| `我今天心情不太好……答案：` | `今天我心情不太好，想和您聊聊。` | `谢谢你，最近有什么好玩的事情吗？` |

24K 版首词经常更合题，但并不稳定：水沸点续写错成“10℃”，人物题虽先说“上海”，后面又把李明写到上海；故事、季节和周末建议也会明显复读。8K 版常在短句后较早输出 EOS。低温 11 条中，四元 token 组重复比例 ≥25% 的数量分别为 5 和 3，但 8K 平均只生成 33.5 token、24K 为 42.2 token；常规温度均长分别为 22.1 和 36.2 token。较短的输出更难累积重复，因此不把这个计数解读为 8K 版生成质量更高。两版都不足以作为可靠聊天模型直接使用。

## 长上下文探针

在开头写入“代号 X17 的物品存放在青松柜”，中间插入不同的验证文本记录，末尾询问存放位置；并做一个对照，把同一事实移到问题紧前。只把续写开头明确写出“青松柜”算成功。

| 8K 模型输入长度 | 事实在开头 | 事实紧邻问题 |
| ---: | ---: | ---: |
| 约 31 token | 成功 | — |
| 约 3,045 token | 失败 | 成功 |
| 约 8,184 token | 失败 | 成功 |
| 约 16,037 token | 失败 | 成功 |
| 约 30,088 token | 失败 | 成功 |

旧版在约 3,065 token 的两种位置都失败；其训练长度只有 2,048，且无法接受 8K 以上输入。新版约 30K 输入推理成功，证明这份权重与实现能跑到该长度；“近处成功、开头失败”的结果说明在这个多文档干扰探针上没有展示有效的远距离检索。它不是标准长上下文基准，也不能把失败全部归因于 RoPE 或窗口设置。

## 判断与下一步

目前如果要选一版作为**短文本续写的预训练基线**，优先保留 24K 版。若继续探索 32K 上下文，8K 版可作为工程基线，但需要另做多位置、多距离的长文任务评测，并确认训练文本是否含有足够的跨段依赖。两版同时改变了词表大小、参数量、训练序列长度和有效训练 token 数；本次结果无法把差距单独归因于词表缩小或上下文变长。验证集来自同一 MiniMind 原文件的随机记录切分，可能与训练集有相似或重复内容；应再用独立来源的中文样本验证结论。

复现脚本入口为 `.venv/bin/python -m train.pretrain.compare_minimind_runs`，见 [对比脚本](../../train/pretrain/compare_minimind_runs.py)。逐条生成与分数当时保存于 `output/minimind_24k_vs_8k_20260927.json`；本机目前缺少该 JSON 和对应最终 checkpoint，不能直接承诺在本机复现。`output/` 被 Git 忽略。
