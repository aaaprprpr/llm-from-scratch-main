# 语料清洗台操作参考

操作入口统一在 [根 README](../../README.md#语料清洗台)。本文保留导入、审核、清洗和产物之间的约定；参数和来源选择以配置与设置页为准。

## 导入与队列

清洗台从 `configs/data_pipeline.json` 中已下载的来源选择数据，支持 MiniMind JSONL 和本地 Hugging Face Dataset。来源格式由 `record_adapters.py` 适配，包括文章、分类正文、问答、instruction/input/output、ShareGPT 和 role/content 对话；这里只提取已有文字，不转换为 SFT/DPO 样本。

导入页先生成不可变 Raw Snapshot，再对正文和标题执行繁体转简体，生成版本化 Review Snapshot。原始下载文件保持不变；标注页直接读取 Review Snapshot。已导入来源在“已导入”中继续使用，旧 Raw Snapshot 可以单独生成简体副本。

准备完成后选择或新建项目，创建全量队列，再进行人工查看或自动清洗。正文保存在 HF Dataset/Arrow，SQLite 保存项目、实际发生的审核操作和事件；全量队列按 ordinal 映射，不预写全部待办条目。

CLI 的核心顺序是：`inspect → preview → import → prepare → project-create → source-attach → queue-full → show-item/review-* → materialize`。Mapping 可选择文本、标题、ID 和来源字段，也可指定 `record_adapter`；自定义字段路径应指向字符串，数组与对象通过对应 adapter 提取。

## 人工编辑与单条清洗

页面直接编辑训练正文，支持撤销和原文对照。未修改的翻页不产生新的“待定”审核；有修改时明确保存保留或丢弃。人工明确决定优先于先前批量结果。

“自动清洗并保存本条”调用设置页的单条模型。完整结果直接写入文档审核记录；仍有未完成分块时不保存为最终正文。页面显示保存状态和删改数量，右侧可查看原文。

“重置本条清洗”恢复导入时准备后的原文，标记待复核，并屏蔽该条旧批量结果；该条重新确认或清洗完成前不进入合并语料。重置后重新自动清洗会绕过旧的完成报告缓存。

编辑器按换行分块，连续空行作为分隔符保留；删除单行不额外插入空行。清洗器会把长行再拆为判断片段，结果按原文顺序组装。它只保留删除和允许的文字整理，不用模型生成的改写替换原文；无效局部修订不会使同块的有效删除失效。

## 批量、暂停与续跑

批量任务使用设置页勾选的来源，较快来源在槽位空出后继续接新条目。来源运行或鉴权故障会停用该来源，其他可用来源继续处理。单篇文本超过处理范围时记为该条失败，不停用整个来源。

页面“暂停”停止派发新文档，等待正在执行的调用和结果落盘；不会中断已经发出的 HTTP 请求。关闭浏览器不暂停后端任务。服务重启后任务可从进度文件续跑，已完成条目复用，未完成条目优先重试；切换批量来源前先暂停任务。

明确的内容敏感拒绝留待人工查看。普通未完成可在另一个勾选来源上再尝试，付费 DeepSeek API 是否补救由独立开关控制；它不领取正常新条目。记录中的尝试次数包含失败与重试，不等于成功条数或 HTTP 请求数。

通用 CLI 为 `python -m dataset.label.cli llm-clean-batch --queue-id your_queue_id`，可加 `--limit`、`--workers`、`--max-requests`、`--data-root` 和 `--output-directory`。网页和 CLI 指向同一进度目录时，共用任务锁。`./clean-batch` 是指定 Wiki 队列的快捷脚本。

## 产物与合并

| 产物 | 用途 |
| --- | --- |
| SQLite 文档审核记录 | 人工确认与单条自动清洗正文 |
| `cleaned.jsonl` | 批量已经完成并保留的正文，按完成顺序写入 |
| `progress.jsonl` | 各次尝试的序号、状态、耗时、字符数和模型用量 |
| `manifest.json` | 批量任务状态、速度和计数 |
| `effective_cleaned.jsonl` | 人工与批量结果合并后的最终正文，按队列顺序排列 |
| `effective_manifest.json` | 合并时的修订、进度与条数 |
| `llm_suggestions/` | 模型响应、分块与操作记录，用于恢复和追溯 |

批量中间结果不能直接代表人工修改后的最终数据。点击“生成合并语料”输出 `effective_cleaned.jsonl`，人工明确决定优先；待复核和未完成条目不进入结果。人工修改或批量进度变化后，旧合并文件会标记需要重新生成；全量任务完成时自动合并一次。

CLI 的 `materialize` 仅基于人工审核事件生成保留来源信息的快照，不包含最新批量合并结果。bin 构建器只接收统一本地 Dataset / Arrow 中间格式目录，输入路径在 `configs/build_bin.json` 的 `build_bin.input` 指定。`effective_cleaned.jsonl` 等 JSONL 成品须先由上游规范化为该目录格式，再交给 bin 编码；bin 不再直接读取 JSONL 或根据来源名选择输入。

## 模型与凭据

设置页分别选择单条模型、批量来源和付费补救开关。服务配置在 `configs/label.json`；根目录 `.env` 提供凭据，系统环境变量优先。配置或 `.env` 改动后重启清洗后端。

| 来源 | 配置入口 |
| --- | --- |
| DeepSeek API | `DEEPSEEK_API_KEY`，可选 `DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL` |
| DashScope API | `DASHSCOPE_API_KEY`、`DEFAULT_MODEL`，可选 `DASHSCOPE_BASE_URL` |

用户已删除 `deepseek-web-api/` 网页聊天适配和凭据导出脚本目录。清洗台仍保留旧网页 provider 的选项和调用代码，但缺少请求脚本，当前不能使用这些网页来源；正式 API、本地 Qwen 和 Laya 的配置继续有效。网页请求格式只作为 [历史记录](../历史记录/2026-09-28-网页聊天接口请求记录.md) 保留，不是现行运行入口。

本地 Qwen 服务来自同级 `qwen/` 项目，实际选择并执行本地清洗时才启动；清洗台启动本身不加载 Qwen。日志位于 `dataset/label/data/local_model.log`，清洗台启动的服务在退出时释放。

Laya 使用本项目内的 Python 运行时与 `dataset/label/models/laya_wiki_cleaning_v1/`，无需另起服务。它是针对维基语料微调的实验分类器；基础权重与其他数据源的适用范围见 [基础评测](../历史记录/2026-09-30-Laya基础分类权重评测.md)、[微调评测](../历史记录/2026-09-30-Laya语料清洗微调评测.md)。

历史探针与人工对照保存在 `dataset/label/experiments/`，不参与正式队列或预训练。固定队列条数、旧快照修订和当时模型速度见 [历史文档目录](../文档目录.md)。
