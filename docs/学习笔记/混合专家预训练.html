MoE：按 token 选择 FFN

学习笔记，2026-10-05 整理。正文数值以 12 层、576 隐藏维度、1536 FFN、24,576 词表为例；当前默认模型仍是普通稠密 Transformer，本页不表示项目已启用 MoE。

MoE 要解决的是：怎样让模型拥有更多参数，又不让每个 token 都承担执行全部参数的计算成本？理解它，需要把三件事连起来：专家保存什么，路由器怎么选择，预测下一个 token 的误差怎样训练这些选择。

从已有的 FFN 理解专家

先看普通 Transformer。一个 token 经过注意力层后，已经把能看到的上下文信息融合进自己的隐藏向量。接下来的 FFN 对这个向量做非线性变换，输出仍然是同样的维度，再加回残差流。虽然一批 token 会被放在一起做矩阵运算，但 FFN 对每个位置分别计算；它本身不在不同 token 之间交换信息。

在你当前的模型里，这个 FFN 是 SwiGLU。设输入向量 x 的维度为 D，中间维度为 F。W₁ 和 W₃ 分别把 D 维映射到 F 维，一条分支经过 SiLU 后与另一条分支逐元素相乘，最后 W₂ 把结果映射回 D 维：

现有 FFN · 按列向量记法
FFN(x)=W2[SiLU(W1x)⊙(W3x)]

普通密集 FFN 的特点是：这一层的所有 token 都使用同一套 W₁、W₃、W₂。无论输入是什么，都完整执行这一套变换。把 F 增大，可以增加参数容量，但每个 token 的矩阵计算也随之增大。

MoE 把这一套 FFN 扩展成 E 套参数独立的 FFN，再为每个 token 只选 k 套执行，其中 k 通常远小于 E。每一套 FFN 就叫一个专家。增加 E 主要增加可供选择的参数；控制 k 则控制单个 token 要执行多少专家。这种“根据输入只执行部分网络”的方式叫条件计算。

这里的专家是一层中的一个 FFN，不是一个完整语言模型。它不独立处理整篇文章，也不单独输出词表概率。多个选中专家各自输出一个 D 维向量，合并后仍是 D 维，因而能够接回原来的 Transformer。不同 MoE 层通常各有自己的路由器和专家，某个 token 在上一层选了专家 0，不代表下一层也要选专家 0。

路由器也是一个可学习的模块。它先把 x 映射为 E 个分数，再决定执行哪些专家。被选中的专家编号集合记为 S，合并权重记为 α。下一节将它们逐项展开。

注意不要把两种“门控”混在一起。SwiGLU 内部的门控，决定一个 FFN 内哪些中间特征通过；MoE 的路由门控，决定整个 token 交给哪些 FFN。一个 MoE 专家内部仍然可以使用 SwiGLU，二者处于不同层次。

一次前向：打分、选择、计算、合并

假设有 4 个专家。路由矩阵的每一行都与 x 做一次点积，得到 4 个实数分数，也就是 logits。softmax 将它们转成非负、总和为 1 的概率。这些概率表达当前路由器对专家的偏好，不代表它已经分别运行了 4 个专家、比较过谁的输出更好。如果先执行全部专家再挑选，稀疏计算的收益就没有了。

MoE · 路由概率 → 选专家 → 加权输出
p=softmax(Wrx),S=Topk(p) y=∑i∈SαiFFNi(x),αi=pi∑j∈Spj

Wr 的形状是 E × D；p 是长度为 E 的路由概率向量；Top-k 取出概率最大的 k 个专家编号。上式采用“只对选中概率重新归一化”的权重定义，所以选中专家的 α 之和为 1。它是一种常见选择，并非所有 MoE 都必须采用；尤其 k = 1 时，会产生后文要解释的梯度问题。

例如，一个 token 得到的概率是 [0.60, 0.30, 0.08, 0.02]。Top-2 会选择专家 0 和专家 1。只在被选中的概率之间归一化，得到 α₀ = 0.60 / 0.90 = 2/3，α₁ = 0.30 / 0.90 = 1/3。随后才真正执行这两个专家；专家 2 和专家 3 对这个 token 不做 FFN 计算。

为便于手算，假设专家 0 的输出是 [3, 0]，专家 1 的输出是 [0, 6]。合并就是逐坐标加权：

y=23[3,0]+13[0,6]=[2,2]

整个向量会分别送给两个专家，而不是把向量前半截给专家 0、后半截给专家 1。合并也不是拼接：每个专家的输出都是 D 维，加权后仍为 D 维。如果改成 Top-1 并把选中权重归一化为 1，这个 token 的 MoE 输出就直接等于专家 0 的输出。

实际训练会同时处理 N = B × T 个 token。每个 token 都有自己的选择，所以要把选中同一专家的 token 暂时聚在一起，做一次批量 FFN 计算，再按原来的 token 位置把结果放回去。Top-2 的一个 token 会出现在两个专家的输入批次中，回填时把两份加权输出加到同一位置。这就是单卡上“分发与合并”的实质。

“每 token 激活 k 个”不意味着“每 batch 只使用 k 个”。这批 token 可以共同覆盖全部专家。若 N = 1000、k = 2，就有 2000 次 token→专家分配；只是每个 token 自己只执行两个专家。所谓稀疏性是相对于单个 token 的路径而言的。

路由依据是当前隐藏向量，而不是固定的词编号。相同的词在不同上下文里有不同的表示，因此可以走不同专家。专家也没有预先贴上“数学”“中文”这样的标签；它们能否形成有用的分工，要看后续训练。

总参数增加，不代表比原 FFN 更省计算

你最初说“提高参数量，减小活跃参数和计算量”，这里必须指定比较对象。假设一个原始 FFN 有 P 个参数，把它换成 4 个同样大小的专家，每次选 1 个，那么总专家参数变成 4P，而每个 token 仍使用 P。与原来的 FFN 比，是总参数增加、主要计算基本保持；与把全部 4P 参数都执行一遍的密集 FFN 比，才是减少活跃参数和计算。

这个区别可以直接从 SwiGLU 的三块矩阵推出。两块矩阵的形状为 F × D，另一块为 D × F，均无偏置，因此一个专家有 3DF 个参数。E 个专家总共有 3EDF；一个 token 执行 k 个专家，则涉及 3kDF 个专家参数。

P全部专家=3EDF,P每 token 专家=3kDF FLOPsFFN / token≈6kDF

三块无偏置矩阵各有 D × F 个参数；乘法和加法各计 1 FLOP。此式只计算前向矩阵乘，未计 SiLU、逐元素乘、路由、索引、反向及优化器。

代入你当前的 D = 576、F = 1536，一个 FFN 有 2,654,208 个参数。换成 4 专家 Top-1，单层专家总参数约为 10.62M，但每 token 仍只执行约 2.65M 的专家参数。若保持专家宽度不变却改成 Top-2，主要 FFN 计算就约为原来的两倍；它不会因为名字里有“稀疏”就自动比原模型更省算力。

另一种选择是把每个专家宽度缩小。例如 Top-2 搭配 F = 768，两个半宽专家的主要矩阵计算合起来，约等于原来一个 F = 1536 的 FFN。但“两个半宽专家的加权和”和“一个完整宽度 FFN”是不同的函数结构，不能仅凭 FLOPs 相同就认为表达能力或训练效果相同。下面的计算器把 E、k、F 分开，正是为了看到这三个变量各自改变什么。

整模总参数按当前配置精确计数：12 层、词表 24576、共享 embedding / lm_head、标准多头注意力；12 个 FFN 全换为 MoE。路由器参数每层另加 E × D。

上面的整模参数还包含注意力、词嵌入和输出层，所以不能把“4 个专家”直接理解成“整模型参数乘 4”。路由器自身也有 E × D 个参数，并且每个 token 都要计算所有 E 个路由分数；稀疏掉的是专家 FFN 的执行，并没有免除路由打分。

不执行一个专家，不等于不存储它。它必须保留权重，之后收到 token 时才能计算；训练还需要相应梯度与优化器状态。另一方面，同样数量的矩阵运算，被拆成多个小批次以后未必有原来一个大批次快，分发与合并也有开销。所以 MoE 给的是“以稀疏计算使用更大参数容量”的结构，实际速度和效果仍取决于训练规模与实现。

预训练时，谁在教专家，谁在教路由器

换成 MoE 后，预训练的主任务不变：给定前面的 token，预测下一个 token。没有额外的数据标签告诉模型“这句话应该用专家 2”。设训练序列中的 token 为 u₁、u₂……，语言建模损失仍然是：

Lnext-token=−1N∑t=1NlogPθ(ut+1∣u1:t)

这里 N 表示参与损失计算的预测位置数，θ 包含整个模型的训练参数。正确 token 的概率越低，损失越大。这个误差从输出层往回传，经过后面的 Transformer 层，最终到达当前 MoE 的合并输出 y。

假设到达 y 的梯度是向量 g，也就是 ∂L/∂y。记专家 i 的输出为 eᵢ。由于 y 是各个 αᵢeᵢ 的和，反向传播自然分成两条路：

∂L∂ei=αig,∂L∂αi=gTei(i∈S)

第一条进入专家内部，更新它的 SwiGLU 参数，使它以后处理类似表示时更有助于降低预测误差。第二条改变合并权重；只要权重到路由分数之间还保留可微路径，就能进一步更新路由矩阵。这就是路由器获得任务训练信号的来源。它没有直接拿到“最佳专家”的标签，而是从自己的选择和合并方式对最终预测造成的影响中学习。

对当前 token 没被选中的专家，没有执行相应 FFN，也就没有这条 token 的任务梯度。其他 token 如果选中了它，它仍然会得到它们的训练信号。这里说的是数据产生的梯度，不是说一个未被选中的参数绝对不会受到优化器动量或权重衰减的影响。

这也说明“专家分工”是怎样可能出现的：路由器让不同输入更多地进入不同专家，各专家再被各自收到的数据更新，之后路由又依据新的模型状态继续选择。这个共同学习过程可以形成分工，也可能偏向少数专家；新增专家数量本身不保证分工一定发生。

同一张卡，也会有专家学不到东西

你提出的单卡疑问，在硬件层面是有道理的。假设 1000 个 token 使用 Top-1，专家大小相同、没有容量截断，也不考虑实现开销，那么无论分成 [250, 250, 250, 250]，还是 [1000, 0, 0, 0]，都执行了 1000 次单 token 的专家 FFN。所有专家又都在同一张卡上，不存在“某张卡独自过载、其他卡等它”的跨卡问题。甚至集中到一个较大的矩阵批次，有时还更容易利用 GPU。

但训练不仅关心这一步算了多少，还关心这些计算更新了哪些参数。如果持续采用第二种分配，专家 0 不断接受任务训练，而另外三个专家几乎没有机会学习。它们虽然占据了参数空间，却没有充分参与当前数据的建模。你原本想借 MoE 增加可用容量，实际却可能长期只用到其中一部分。

这种偏向可能在早期就出现。路由器的初始分数有小差别，硬 Top-1 会把小差别变成离散的选择差别；被更多选择的专家接受更多数据更新，其他专家缺乏训练机会，之后这种差距可能继续维持。这通常被称为路由塌缩。它不是每次训练都必然发生，但是否同卡并不能消除这种学习上的不均衡。

负载均衡项就是给路由器增加一个约束：优化预测误差的同时，避免长期把绝大多数 token 都交给少数专家。它不替专家学习具体知识，也不强制给每个 token 平均使用全部专家。要理解它怎样工作，先区分两个很容易混淆的统计量。

对一批 N 个 token，fᵢ 表示“实际上有多少比例的 token 选了专家 i”；p̄ᵢ 表示“路由器给专家 i 的概率，跨 token 平均之后有多大”。前者来自硬选择，后者来自 softmax。它们不是同一个东西：如果每个 token 的概率都是 [0.26, 0.25, 0.25, 0.24]，平均概率看上去很均匀，Top-1 却会让所有 token 都选专家 0，实际负载是 [1, 0, 0, 0]。

Top-1 · 从整批 token 统计负载
fi=1N∑t=1N𝟙[st=i],p¯i=1N∑t=1Npti Lbalance=E∑i=1Efip¯i,L=Lnext-token+λLbalance

均衡损失来源：Switch Transformer §2.2。

式中的 st 是 token t 选中的专家编号，𝟙[st = i] 在选中专家 i 时取 1，否则取 0。这组公式先统计实际分配 f，再把它与平均路由概率 p̄ 做内积。系数 E 用于调整专家数量变化带来的尺度；λ 控制均衡项相对于语言建模损失的影响。

反向传播时，f 被视为已经观察到的常量，梯度经由 p̄ 回到路由器。暂时把各专家概率看成可调的分配，fᵢ 越大的专家，每增加一份概率，对均衡损失的增加就越大；相反，把概率移向 fᵢ 较小的专家更有利于减小这个损失。softmax 的概率之和固定为 1，所以这个更新会改变专家之间的相对偏好，而不只是把所有分数一起降低。

为了看清梯度方向，令一个 token 的路由 logit 为 ztj = wj · xt + bj。下面的实验固定 x 和 w，只更新每个专家的偏置 b；代入 softmax 导数，可以得到：

∂Lbalance∂bj=EN∑t=1Nptj(fj−∑i=1Efipti)

括号中的第二项，是当前 token 按概率加权得到的平均负载。若某专家的 fⱼ 高于这个平均负载，它对该 token 的梯度贡献为正；梯度下降会倾向于降低它的偏置。低负载专家则可能得到相反方向的更新。对所有 token 求和，就得到表中用于更新 b 的梯度。每一步按 b ← b − ηλ∇bL 更新，再重新计算 Top-1，某些 token 便可能切换专家。

均匀负载并不要求均衡损失为零。当所有 fᵢ = 1/E 时，由于各专家的平均概率之和为 1，这个损失正好等于 1，而且在把 f 视为常量的反向过程中，梯度为零。反过来，损失接近 1 也不能单独证明负载均匀：前面 [0.26, 0.25, 0.25, 0.24] 的例子虽然全部选中专家 0，损失却只有 4 × 0.26 = 1.04。所以还要直接看实际分配计数。

实际预训练同时存在两个目标：语言建模损失推动预测变好，均衡项推动专家得到更充分的使用。λ 太强时，路由可能过分追求分配均匀；太弱时，又可能阻止不了集中。均衡是训练约束，不是“所有专家能力都已提高”的证据。尤其小模型和有限数据下，在 token 总量与 k 固定时，专家更多还意味着每个专家平均能分到的数据更少，不能把增加专家数直接等同于效果提升。

Top-k 不可微，路由器为什么还能训练

前面说路由器从合并权重接收任务梯度，这里还缺一个关键条件：从权重 α 到路由分数之间，真的存在有效梯度吗？“模型可以执行前向”并不能保证这条学习路径成立，Top-1 尤其容易出现这种问题。

先区分“选谁”和“给多少权重”。Top-k 输出的专家编号是离散的：当前分数最高的是专家 0，把分数稍微改一点，编号仍然是 0；只有跨过另一个专家的分数时，编号才会跳变。通常的反向传播不会对这个整数选择求导，而是在当前选中的分支上继续传播。选中的概率仍然是连续可微的，所以只要输出确实依赖这些概率，就可以沿这条路径更新路由器。参数更新后，下次前向的排序又可能发生变化。

下面三幅图共用同一个概率。左边画真实前向函数 pₛ→α，右边画反向传播的路径和局部导数；两者必须分开看。

直接保留选中概率

y=psFFNs(x)

这里 s 是选中的专家。概率 ps 改变时，y 也会改变，因此任务误差能够通过 ps 回传给路由器。代价是前向输出会乘上这个概率：ps = 0.6 时，专家输出只有原来的 0.6 倍。

Top-1 直接归一化

αs=psps=1,∂αs∂ps=0

只有一个被选中的概率时，除以选中概率之和，就是 ps 除以它自己，结果恒为 1。路由概率在当前选择不变的范围内怎样变化，都不会影响这个权重。于是任务损失通过合并权重回到路由器的梯度消失。专家依然能学，路由器也仍可收到均衡项的梯度，但它失去了这条来自预测任务的权重学习信号。

直通估计：前向为 1，反向保留梯度

αs=ps−stopgrad(ps)+1

stopgrad 保留数值，但阻断梯度。前向时，两项概率相消，α = 1；反向时，只有第一项 ps 传梯度，因此 ∂α / ∂ps = 1。这是人为指定的替代梯度，不是硬路由的真实导数。

比如 ps = 0.6，前向算的是 0.6 − 0.6 + 1 = 1；反向把第二个 0.6 当作常量，得到 1 − 0 + 0 = 1。它把“前向要保持的数值”和“反向采用的导数”分开定义，使输出不被概率缩小，同时仍让路由器收到一条替代的任务梯度。本地 MiniMind 的 Top-1 分支采用的就是这个思路。

Top-2 的选中概率归一化不同：α₀ = p₀/(p₀+p₁) 还取决于两个专家的相对分数，并非恒定值，因此通常仍保留权重梯度。但硬选择边界依旧没有直接求导；在当前选择固定时，这种归一化的任务梯度直接作用于选中专家的相对 logits；未选中专家的路由分数可由均衡项等路径调整，而其 FFN 参数仍需要等收到 token 才有任务梯度。

因此，学习 MoE 时需要同时追踪两件事：前向到底执行了哪些专家，反向误差到底经过哪些路径。只看到 token 被分给多个 FFN，还没有完整理解训练；必须再确认专家能收到数据梯度、路由器能学到有用的选择，以及这种选择没有长期闲置大部分专家。
