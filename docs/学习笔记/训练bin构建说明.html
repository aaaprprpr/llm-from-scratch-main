训练 bin 构建说明

dataset/data_pipeline/build_bin.py 把统一本地 Dataset/Arrow 中间格式编码成训练使用的连续 token ID 文件。它不识别 MiniMind 或其他来源，不下载、不清洗、不做字段适配；上游交付的正文在这里被直接编码。

中间格式与编码边界

输入是一个本地 Dataset 目录，包含字符串 text 列，每条记录是一篇完整正文。可以附带 doc_id、来源和修订等信息；bin 只读取 text，这些信息不混进训练正文。

textdoc_id（可选）
你好。doc-1
今天下雨。doc-2
明天见。doc-3

参数集中在 configs/build_bin.json。build_bin.input 直接填目录路径；默认输入目录为 dataset/data_pipeline/data/intermediate/，输出到 dataset/data_pipeline/data/bins/。输入目录是上游成品的位置，不由构建器自行生成。

dataset/storage.py 提供通用读取器，兼容 HF 的 save_to_disk 目录与已有 dataset.json + Arrow 分片目录，返回同一种 Dataset 接口。构建器不导入清洗台后台，也不读取下载来源注册表。

旧 preprocess.py 已删除，MiniMind 原始 JSONL、来源名和旧预处理别名不再接入 bin。清洗台目前导出的 effective_cleaned.jsonl 需由上游统一成中间 Dataset；上游下载与存储规范会另行整理。编码器的输入约定由文本记录决定，与数据来自哪个网站或哪个清洗器无关。

实际执行的处理

首先读取独立的 bin 配置和本地目录。Dataset/Arrow 按批次访问 text，无需将全部正文变成常驻内存的字符串列表。读取器保留中间 Dataset 的指纹，元数据记录的是这份输入的身份。

接着用固定 seed=42 选择整条记录属于训练还是验证。脚本把记录分为每块 1,000 条，打乱块顺序，再打乱每块内部顺序。这是分块打乱，不能等同于把全部记录一次做完全随机排列。

正文按每批 512 条交给分词器。编码不截断，也不补齐；每条记录末尾追加一个 <|endoftext|>。训练记录与验证记录分别拼接，再顺序写入各自的 bin。长文不会在这里切成 2,048 或 4,096 的固定窗口，训练阶段才从连续 token 流中取窗口。

当前词表的 token ID 用 uint16 存，每个 ID 占 2 字节。bin 只有这些整数，不保存 JSON 字段名、正文或文档标题。文档末尾的 EOS 同样是一个整数。

bin 文件字节数 = token 数 × 2（当前 uint16）

并行调度单进程与多进程两种路径，初始化分词器；最多保留 worker 数两倍的待处理任务，并按提交顺序取结果。
