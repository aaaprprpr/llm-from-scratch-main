# Laya 本地分类接入与实测

模型来源：同级 `laya` 项目，Laya 0.3.22，Apache-2.0；运行代码已复制到项目根目录 `laya/`，中文 `multilingual` 检查点复制到 `dataset/label/models/laya_multilingual/`（约 647 MB，已加入 Git 忽略）。当前虚拟环境已有 Torch、Transformers、safetensors、Hugging Face Hub 和 NumPy，推理不需要网络或独立服务。

清洗台设置页现在有「Laya 本地分类（实验）」来源。它复用现有的删除建议组装、报告缓存、单条保存、批量进度和导出逻辑；换行形成的块优先作为一个判断单元，超过 1200 字符才继续拆分；每个单元只得到「保留/删除」判断，不能像生成式模型那样裁剪 unit 内部文字、修补空白或拼接断句。一次批量推理最多送 16 个片段，显卡内只保持一份模型，推理时串行访问。原 Qwen 27B 不再随清洗台启动，只在实际选用它清洗时加载。

## 本机结果

- RTX 5070 Ti：冷加载约 4.3 秒；12 个短中文片段约 0.6 秒。首次进入完整清洗路径约 5.8 秒，再次命中报告缓存约 0 秒。
- 人工设计的 16 个正文/残片例子，四种不同提问方式分别判对 7～10 条。
- 从已有完整清洗报告中抽取 50 个保留 unit、50 个删除 unit 作为**参考标签**，当前提问方式判对 51/100：保留召回 10/50，删除召回 41/50。这些是原清洗器的标签，不能当作人工金标准。
- 将删除概率阈值提高到 0.9，仍误删 4/50 条参考正文，只正确删除 2/50 条参考残片；阈值 0.95 时误删 1 条且正确删除 0 条。
- 端到端实测留下「参考文献」，删掉「数学是研究数量、结构、变化以及空间等概念的一门学科。」。这说明当前零样本权重不适合直接替换现有中文语料清洗模型。

因此只添加为**可选实验来源**，不修改当前单条或批量模型选择，不自动续跑已有队列。建议先利用已有人审/清洗记录制作训练集，微调或校准 Laya，再做独立抽样评估；当前权重直接跑全量会大量误删正文。


## 为什么会误删：按当前项目复核（2026-09-30）

Laya 的接口是 `predict(state, questions)`，并非聊天补全。当前接入真正送进模型的是每个判断单元的文字和 `QUESTION` 中的二选一问题；报告里的 `system_prompt` 只是缓存标识，不参与推理。此前 Laya 继承了聊天清洗器的 `split_units`：即使导入时已按单换行分块，块内仍按「。！？」拆句，判断时也没有标题或相邻句。对完整段落来说，这会丢掉大量语义线索。现已让 Laya 优先按换行块判断，长于 1200 字符的块仍拆分，其他聊天模型的切分不变；缓存标识已更新，旧版 Laya 建议不会被当作新版命中。

为了分开检查「切分」和「提问方式」，用已有完整清洗报告的**建议**作伪标签，从不同文档抽取参考保留和参考删除样本。参考标签来自先前 LLM，未逐条人工确证；采样刻意两类各半，因此下表不能解释成真实语料准确率。测试脚本是 `dataset/label/experiments/laya_question_probe.py`，只读报告和本地模型，不写正式队列。

| 留出集比较 | 参考应保留 160 块中完整留下 | 参考应删除 160 块中完整删掉 | 参考应保留却被删至少一部分 |
| --- | ---: | ---: | ---: |
| 整个换行块判断 | 63 | 117 | 97 |
| **同一批块**继续拆句后逐句判断 | 23 | 116 | 137 |

这说明过细切分确实明显加重误删，但整块判断仍误删了约六成参考正文，不能只靠切分修好。在另一个按句抽取的 320 个留出样本上，当前问法正确 157 个，其中 160 个参考正文只留下 29 个。把标题、前后片段加进 `state` 后，同组样本正确 115 个，正文留下 32 个；改为更直白的中文选项正确 178 个，正文留下 32 个。这里的上下文方案未经任务训练，结果仅说明**当前零样本权重**不会自动从额外字段得到收益，不能推断训练后的上下文无用。不同抽样集合的分数也不能直接相减归因。

本地权重在项目自带的 `zh_decision_bench.jsonl` 上，`choice` 正确率约 85.8%，说明加载和二选一接口能正常工作；这份基准是其他中文决策任务，不能代表中文预训练语料筛选。`noul` 问答在同一基准上约 58.2%，把 `choice` 换成 `noul` 也不是捷径。[Laya 官方 README](https://github.com/NandhaKishorM/laya)和[多语言检查点模型卡](https://huggingface.co/convaiinnovations/laya-multilingual)都把公开基础权重定位为可针对任务微调的决策底座，而非已训练好的中文语料清洗器；官方的跨工作流示例也是微调后才明显提升。[官方微调说明](https://github.com/NandhaKishorM/laya/blob/main/docs/finetune.md)明确给出 `state` / `questions` / `gold` 训练格式和独立校准、测试流程。

## 对这项任务的合适用法

1. 保持「一条文档内逐块、`predict_batch` 批量推理」的速度优势。每个判断仍独立，但可把标题和前后相邻块作为**明确标注的辅助上下文**放入 `state`；标签始终只针对目标块。须用同样结构训练和推理，再用留出文档比较，否则追加上下文可能适得其反。
2. 从人工确认的清洗记录制作块级标签。LLM 建议可以做候选，但不能直接当金标准；含局部删改或「正文 + 杂质」混合块要单列，不能硬标为整块删除。按文档 ID 分训练、校准、测试集，防止一篇文章的相邻句分散进两边。测试重点报告**正文误删率**、杂质删净率，以及不同长度和数据源的表现。
3. 用项目旁边 Laya 的 `research/scripts/finetune_single_device.py` 从本地 multilingual 权重训练二选一任务，训练输入为 `{"state": ..., "questions": {"body": ...}, "gold": {"body": {"probabilities": {"keep": ..., "drop": ...}}}}`。可先把人工硬标签转为接近 0/1 的软目标；若有可靠教师概率再用其分布。[单卡脚本](https://github.com/NandhaKishorM/laya/blob/main/research/scripts/finetune_single_device.py)与[官方微调说明](https://github.com/NandhaKishorM/laya/blob/main/docs/finetune.md)提供训练及校准实现，尚未在本项目语料上实际训练。
4. 推理时把不确定或混合块交给现有生成式清洗器，或先保留待人工核验。Laya 只能整块保留或删除，不能删除块中某半句话、修补断句。校准只能让置信度更可信，不改变二选一的最高分标签；现有权重调高删除阈值几乎同时失去删除能力，不能充当微调。

当前 Laya 仍为**实验来源**。整块切分已修正，但在拿到有人工金标准的留出集并验证正文误删率前，不宜选它直接跑大批量正式清洗。未启动或修改正在运行的队列。
