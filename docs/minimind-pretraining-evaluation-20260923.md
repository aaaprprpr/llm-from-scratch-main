# MiniMind 首轮预训练评测（2026-09-23）

> 范围更正：这次 1,987 步训练只用了 `pretrain_t2t_mini.jsonl`（原始文件 1,241,043,656 字节）。同仓库还有用于完整主线训练的 `pretrain_t2t.jsonl`（8,275,074,893 字节），当时没有下载或用于训练。因此本文所有 loss、样例和建议均只适用于 mini 版，不能代表完整版数据的训练结果。

结论：这次训练在已记录的指标上稳定，最终 checkpoint 最好；模型已学到一些中文句式，但知识、上下文理解和回答相关性仍很弱，尚不满足日常聊天需求。不能把 loss 下降等同于聊天能力达标，也没有依据把这次生成差直接认定为数据脏。

## 对象与方法

- 训练机：`192.168.1.3`，RTX 5070 Ti 16GB；评测前 GPU 空闲。
- Run：`/media/tdt/新加卷/llm-from-scratch-main/output/train_logs/run_20260923_011738`。
- 模型：61,945,920 参数，词表 24,576；AdamW，约一遍 MiniMind mini，1,987 次更新、260,440,064 个训练 tokens。
- 读取全部 20 次训练中验证记录，实际加载 500、1,000、1,987 步 checkpoint 复测。
- 复算训练时固定的 train/val 各 32 个窗口（各 65,536 tokens）；另在同一验证文件上以新 seed=20260923 分层抽取 128 个窗口（262,144 tokens），三份 checkpoint 共用。新窗口并非新的独立数据集，可能与原窗口有部分重叠。
- 每份 checkpoint 测 11 个中文续写/问答提示：temperature=0.3、top_p=0.9、最多 80 个新 tokens、固定随机种子。最终 checkpoint 另测 temperature=0.7、三个种子，共 33 个样本。合计 66 个生成样本。
- 使用普通文本续写输入，没有假设模型已接受 ChatML 或 SFT。小规模人工设计提示仅用于诊断，不是标准能力榜单。

## 训练与验证

| checkpoint | 固定 train loss | 固定 val loss | 新抽样 val loss |
| ---: | ---: | ---: | ---: |
| 500 | 4.5606 | 4.8367 | 4.6732 |
| 1,000 | 3.7401 | 3.9903 | 3.8622 |
| **1,987** | **3.1879** | **3.4449** | **3.3282** |

固定窗口复算结果与训练日志一致。训练中的 20 次 val loss 从 7.7536 持续降到 3.4449，没有中后期反弹；最终 checkpoint 是本次全部已保存模型中日志验证 loss 最低的。

最后一段（1,500 步之后）日志采样的裁剪前梯度范数中位数为 0.552，最大值 1.424。三个实测 checkpoint 的参数均为有限值，QKV 权重 RMS 层均值分别为 0.02065、0.02107、0.02120，没有出现旧 run 中那种显著权重增长。以上支持“本次已观察训练过程稳定”，不保证未来延长训练仍保持稳定。

本次验证语料已经更换，不能拿这里的 loss 数字直接与旧 FineWeb run 比较模型优劣；优化器与数据也同时发生变化，不能据此单独证明某一项改动的因果效果。

低温测试中，5 道具有明确目标答案的小题仅 1 道命中（上海）；该数值只描述这 5 个提示，不代表通用准确率。升温到 0.7、换三个种子后，首都、沸点和加法仍答错，“上海”也变得不稳定，因此不是单次抽样偶然失败。

最终模型的 token 四元组平均重复比例：低温 11 样本为 2.24%，常规温度 33 样本为 7.67%；后者有 3 个样本达到 25% 的高重复阈值。但大量回答很短并提前 EOS，会压低该指标；语义重复、跑题、事实错误仍明显，不能把低四元组重复率解释为回答优质。

## 推理检查与判断

最终模型在 16 个连续生成位置上，FP32 的 KV-cache 增量推理与全上下文重算 top-1 为 16/16 一致，最大 logit 差约 1.72e-5。这项检查没有发现缓存实现错误，但覆盖范围仅为所测提示与长度。

当前实际训练量约为 4.2 tokens/参数，末期验证 loss 仍在下降。结合较弱的语义能力，训练尚不充分是合理的工作假设；此评测没有单独区分训练量、数据覆盖和训练目标的贡献。

建议保留 `ckpt_step_1987.pt` 作为下一阶段起点，优先考虑继续预训练并监控同一验证集合，而不是因为当前输出差直接丢掉模型或重新清洗全部数据。本次只评测，没有修改训练参数、启动续训或覆盖 checkpoint。注意当前入口按约一遍自动结束，直接 resume 最终 checkpoint 不会增加更新步数；后续若决定续训，需要明确扩展训练预算与学习率调度。
